# 更新记录

这里只记录飞牛打包变化与关键升级事项。组件摘要由 `binary.lock.json` 维护。

## 1.0.16

- 成对更新到 CPA Manager Plus `1.14.9`、CLIProxyAPI `8.0.44`。
- `1.14.8` 修复后台刷新时的数据连续性、请求监控的来源归属、配额窗口展示与 xAI OAuth 订阅识别；`1.14.9` 只更新 Go/Node 依赖与 CI 安全检查，不动数据库、配置与凭据格式。
- 升级保留旧配置与数据，无需迁移（`migration_required=false`）；代理最低基线仍为 `v7.3.4`，管理接口与 `access.api-keys` 等 v8 配置键不变。
- `1.14.7` 的大库延迟覆盖索引离线 `cleanup-derived` 指引继续适用，本次不新增维护步骤。

## 1.0.15

- 成对更新到 CPA Manager Plus `1.14.7`、CLIProxyAPI `8.0.32`。
- 保留官方普通 Linux amd64 构建与 v8 管理配置兼容，继续不打包凭证时段插件。
- 更新前保存同一时间点的数据库与归档；已有大库的延迟覆盖索引需停服后离线执行 `cleanup-derived`。
- 发布源码只保留当前打包工程，官方依赖改为按锁下载并进行归档、二进制双重摘要校验。

## 1.0.14

- 成对更新到 CPA Manager Plus `1.14.2`、CLIProxyAPI `8.0.6`。
- 新装默认使用 v8 配置，客户端密钥位于 `access.api-keys`。
- 升级保留旧配置和数据；首次成功的 v8 管理写入迁移布局并保留客户端、管理密钥。
- Shell 脚本作为唯一构建与测试实现，PowerShell 仅作转发。

## 1.0.13

- 更新到 CPA Manager Plus `1.13.2`、CLIProxyAPI `7.3.12`，满足管理器声明的代理最低基线。

## 1.0.12

- 在读取 `/proc/<pid>/exe` 受限时，回退到启动参数与内核短名识别本包进程。
- 启停失败时报告端口占用，避免存活代理被误认为非本包进程而遗留。

## 1.0.11

- CPA Manager Plus 更新到 `1.12.14`，切换官方 Release 二进制，不再需要前端与 Go 编译链。
- 修复服务启动时的进程身份竞态，停止打包凭证时段插件。

## 早期版本

- `1.0.5–1.0.10`：完善升级前停止旧服务、持久 PID、孤儿进程识别、生命周期互斥与健康检查重试，并同步上游版本。
- `1.0.2–1.0.4`：历史凭证时段插件及管理 UI 适配，已由 `1.0.11` 停用。
- `1.0.1`：修复反向代理管理访问与模型 API 认证。
- `1.0.0`：建立原生双服务打包、安装向导及数据保留契约。
